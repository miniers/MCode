# 高还原设计稿

1. 出稿前和每次改稿前，先列出需要用户拍板的细节（布局取舍、信息层级、交互方式、风格方向等），用提问工具给 2 到 4 个选项让用户选，推荐项放第一个；用户没有思路时，先给几个设计方向让用户挑。能从需求或项目里定下来的不问。
2. 不画 ASCII 线稿。UI 方案写成 HTML 文件，放在 `.mcode/design/<主题>.html`（该目录不进 git），一个方案一个文件；同一方案的多个状态或视口并排放在同一个文件里。
3. 先找项目真实的设计 token：CSS 变量文件、Tailwind 配置、主题文件或组件库样式。能引用就用相对路径 `<link>` 引用，只能抄值时照原值抄，不自造颜色、字号、间距、圆角。项目没有 token 时，在文件顶部用 CSS 变量集中定义一套。
4. 交互用原生 JS 写在同文件的 `<script>` 里（展开收起、选中、悬停、状态切换）。不引用外链 CDN、远程字体，不发网络请求，预览的 CSP 会拦截；图标用内联 SVG。
5. 写完或改完调用 mcode 的 `preview_open` 工具打开设计稿（改稿后再次调用 `preview_open` 打开同一文件，预览会刷新）；工具不可用时在回复里用反引号给出文件路径，用户点击即可预览。用户可用标注圈选元素回传修改意见。
